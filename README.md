# Snip

Сокращатель ссылок со статистикой переходов

![CI](https://github.com/Fon911/snip/actions/workflows/ci.yml/badge.svg)

## Возможности

- Сокращение ссылок до случайных 8-значных кодов
- Статистика переходов по каждой ссылке
- Честные HTTP-статусы (400/404, а не 200 на всё)

## Стек

Go, chi, PostgreSQL, pgx, sqlc, goose, Docker, GitHub Actions

## API

| Метод | Путь                | Что делает                                              | Ответ                               |
| ----- | ------------------- | ------------------------------------------------------- | ----------------------------------- |
| POST  | `/api/shorten`      | Сокращает ссылку. Тело: `{"url": "https://..."}`        | `201` + `{"code": "..."}`           |
| GET   | `/{code}`           | Редирект на оригинальную ссылку, `+1` к счётчику кликов | `302` + `Location`                  |
| GET   | `/api/stats/{code}` | Статистика по коду                                      | `200` + `{"code", "url", "clicks"}` |

Ошибки: `400` — кривой JSON или пустой `url`, `404` — код не найден.

## Запуск локально

Нужны: Go 1.27+, Docker, [goose](https://github.com/pressly/goose).

```bash
# 1. Постгрес в докере
docker run -d --name snipdb -p 5400:5432 -e POSTGRES_PASSWORD=secret postgres:16-alpine

# 2. Миграции
goose -dir migrations postgres "postgres://postgres:secret@localhost:5400/postgres" up

# 3. Запуск
go run .
```

Сервер поднимется на `http://localhost:8000`.

## Архитектура

3 слоя handler → service → storage зависимости идут только вниз, handler не знает про storage и тд

handler → дергает service и не знает про storage,парсит JSON, а в случае ошибки переводит её в статус-код

service → в нем находится вся логика которую можно вызвать кроме связей с бд,все связи в storage
Например:
Генерация кода,в редком случае коллизии совершается еще 4 попытки

storage → в нем находится вся логика связей с бд т е все запросы которые мы туда посылает цель этого слоя отдать либо получить данные,что мы будем с ними делать этот слой не знает
